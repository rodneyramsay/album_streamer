## Known Runtime Settings

- `pidap-buttons` is now an event loop with `MAX_IDLE=0.05s` and non-blocking `menu_in` writes.
- `pidap-menu` unlinks `pidap.generated.menu_mode` before the result write and opens `menu_out` non-blocking.
- TFT init script is `S41pirate-tft`; it loads `gpio_backlight` before `panel_mipi_dbi` and sets `Uni2-Terminus18x10`.

## Performance & Optimization Plan

1. **Profile boot time**
   - Add `init=/bin/sh` test, `dmesg` markers, or Buildroot `BR2_TARGET_GENERIC_GETTY_BAUDRATE`/`initramfs` timing.
   - Target `S39wait-eth0`, `S41static-eth`, `S41pirate-tft`/`panel_mipi_dbi` init, and package init scripts.

2. **Trim packages for minimal player image**
   - Candidates for removal: `PHP`, `Python3`, `git`, `nano`, `kbd`, `i2c-tools`, `sox`, `flac`, `vorbis-tools`, `ffmpeg` if not used by player, `util-linux` extras.
   - Keep: `perl`, `alsa-utils`, `rpi-firmware`, `rpi-utils`, `libgpiod`, `openssh`, `ifupdown`, `bash` (or consider `dash`/`busybox` sh).

3. **Build modules into the kernel**
   - Compile `gpio_backlight`, `panel_mipi_dbi`, `fbtft`/`mipi-dbi`, `snd_soc_pcm512x`/`hifiberry`/`rpi-simple-sndcard` paths, and networking into `=y`.
   - Drop `modprobe`/`insmod` calls from `S41pirate-tft` and friends.

4. **Conditional network / SSH for now**
   - `S39wait-eth0` should bail immediately if `eth0` is missing or no carrier; same for `S41static-eth`.
   - Keep `openssh` but only start if a link is detected; or retain manual `S99pidap` dependence.
   - Later: card-only build with no network/SSH.

5. **Pi Zero 2 W / other models**
   - Current build is `arm1176jzf-s`, `bcmrpi` kernel, `bcm2708-rpi-zero` dtb.
   - Zero 2 W needs `bcm2710`/`bcm2837` kernel defconfig, `bcm2710-rpi-zero-2` dtb, and matching `rpi-firmware` variant (`start.elf`/`fixup.dat`). It may need an `aarch64` or `cortex-a53` cross toolchain. This is a separate build config; most rootfs-overlay carries over.

## Menu Pre-Build / Cache Plan

- `pidap-menu` currently builds the artist/album/track tree and reads track offsets every time `show` is received. This causes a 2-3 second lag on first menu open.
- Pre-build everything when the playlist is generated by `pidap-playlist` or when `pidap` loads the album:
  - genre/artist/album lists and indices,
  - track names, durations, and offsets for every album,
  - pre-formatted display strings (e.g., title + 24-char item strings),
  - current-position index for each level.
- Cache on disk as `pidap.generated.menu_cache` (or `menu_cache.pl` / `menu_cache.json`).
- `pidap-menu` `run_menu` loads the cache and skips the tree-building and `get_album_offsets` work.
- If the playlist changes, regenerate the cache; `pidap-menu` can detect a stale cache by mtime/playlist hash and fall back to building it.

## Config Management

Use Buildroot defconfigs for each target combination:

```
configs/pidap_zero_dev_defconfig      # original Pi Zero / Pirate Audio (dev/SSH)
configs/pidap_zero_release_defconfig  # original Pi Zero, card-only/minimal
configs/pidap_zero2w_dev_defconfig    # Pi Zero 2 W (armv8/aarch64, bcm2710)
configs/pidap_zero2w_release_defconfig# Pi Zero 2 W, card-only/minimal
```

The `Makefile` selects the defconfig from `MODEL` and `PROFILE`:

```sh
make -C /home/rodney/album_streamer/buildroot_pidap list-configs
make -C /home/rodney/album_streamer/buildroot_pidap MODEL=zero2w PROFILE=release defconfig
make -C /home/rodney/album_streamer/buildroot_pidap MODEL=zero2w PROFILE=release sdcard-system
```

If `MODEL` and `PROFILE` are both unset, it uses `pidap_defconfig` for compatibility.
